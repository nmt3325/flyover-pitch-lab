# Flyover Pitch Lab for iOS / iPadOS — unsigned IPA

The iOS/iPadOS build uses native `MKMapView` and presents **requested versus actual camera pitch**. Compare the same location using Apple's Maps app to investigate whether the latest Enhanced Flyover imagery is available through public MapKit. This app **does not identify its underlying renderer as 3DGS**.

## Download

1. Open [Actions → Build iOS and iPadOS unsigned IPA](https://github.com/nmt3325/flyover-pitch-lab/actions/workflows/ios-ipa.yml).
2. Open a **successful** run. Download the `FlyoverPitchLab-iOS-iPadOS-unsigned` artifact ZIP.
3. Unzip it to obtain `FlyoverPitchLab-iOS-iPadOS-unsigned.ipa`.
4. In LiveContainer (installed and configured via official [installation instructions](https://livecontainer.github.io/docs/installation)), import this IPA and launch it.

The IPA is **unsigned**: it is intentionally not an installable signed iPhone app. LiveContainer imports/re-signs guest apps where appropriate. Installation and execution with a free Apple ID depend on your LiveContainer setup; no extra MapKit entitlement is needed.

## Maps entitlement

Apple documents `com.apple.developer.maps` as **deprecated** and says "Using Maps no longer requires an entitlement." The Maps capability relates to apps that provide custom routing/directions through Apple Maps, not a regular MapKit view. We do not add any entitlements to the guest app. Note: LiveContainer does **not** inherit guest app entitlements into its host.

## Features

- iPhone portrait: map above a scrollable inspector.
- iPad / landscape: map and inspector side-by-side.
- `Satellite Flyover`, `Hybrid Flyover`, `Realistic Imagery`.
- Tokyo Tower, Shinjuku, San Francisco, New York, or custom coordinates.
- Requested camera pitch 0–90°, one-tap 89°/90°, distance, heading.
- Actual camera pitch, distance, altitude, heading from `MKMapView.camera`; copy measurements to pasteboard.

## Building from source

The repo includes a macOS SwiftPM app (unchanged) and a separate iOS app target generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen).

On an appropriately configured Mac with the iOS SDK:

```bash
brew install xcodegen
bash scripts/build-ios-ipa.sh
```

The output is `dist/FlyoverPitchLab-iOS-iPadOS-unsigned.ipa`. GitHub Actions uses the `xcode-27` runner.

## Caveats

- Flyover and realistic imagery coverage varies by location and OS; request ≠ actual camera pitch.
- Matching Apple Maps visually does not prove 3DGS; a private Apple renderer or data format cannot be inferred from `MKMapView.camera`.
- LiveContainer may have compatibility constraints unrelated to Apple Maps or entitlements; the app has not been tested on a physical iOS 27 device.
- No private APIs, no exporting Apple Maps data, and no unusual entitlements.


## On-device detailed diagnostics (LiveContainer friendly)

The iOS/iPadOS app now saves structured UTF-8 **JSONL** records locally to
\`Documents/FlyoverPitchLab/diagnostics-current.jsonl\`; files rotate through
\`diagnostics-previous.jsonl\` and \`diagnostics-older.jsonl\` at 4 MiB each.
Nothing uploads automatically.

Open **詳細診断ログ** in the controls pane, then tap **全ログを共有** to export
all retained JSONL events through the share sheet, or **表示ログをコピー**
to paste recent human-readable entries.

Events include MapKit start/success/failure loading callbacks with \`NSError\`
domain/code, tile rendering start/completion and \`fullyRendered\`, camera
requests and readback (clamp deltas), location, heading, range, app state,
network interface/connectivity, power/thermal and a watchdog for long loads.
Camera changes are sampled at most four times per second; detailed file
entries at most once per second during map gestures. This is a rolling
log with explicit timestamps and no arbitrary error.userInfo dump.

**Interpretation caveat:** Apple's public MapKit API cannot report server
rate-limit/account quota status, 3DGS availability or raw tile HTTP responses.
A map loading failure or \`fullyRendered=false\` is evidence of a rendering
problem but not direct evidence of a limit. LiveContainer guest-sandbox access
to Documents via Files can vary; use the in-app share/copy controls first.


## Automatic Flyover camera diagnostic sweep

The **自動診断：最大Pitchと描画状況** group on iPhone/iPad runs a
**54-measurement sweep** for all combinations of:

- Renderer: Satellite Flyover, Hybrid Flyover, Realistic Imagery
- Camera distance: 50, 200, 500, 1,200, 3,000 and 10,000 meters
- Requested pitch: 60°, 75° and 89°

The app holds one location and heading constant, applies each camera through
public MapKit, waits for camera settling (and briefly for a render callback),
then records *actual* camera pitch/distance/altitude/heading, rendering
callbacks, app-visible loading starts and error count, and elapsed time.

**Start** from the on-screen control and keep the app in the foreground;
**中断** cancels without losing completed rows. UI controls are disabled
during the sweep and the original renderer/camera are restored after it.
Results appear in the app per renderer/distance and can be shared using
**診断結果CSVを共有**. A full row-by-row CSV is saved after every test to
\`Documents/FlyoverPitchLab/AutoDiagnostic-latest.csv\`, so results survive
an interrupted LiveContainer guest. The earlier JSONL diagnostics also
include \`AUTOTEST.STEP_REQUESTED\` and \`AUTOTEST.STEP_RESULT\` events.

**What a measured maximum means:** the highest *observed* pitch among
the tested requests, capped by the 89° test. It is not proof of the global
maximum or a direct measurement of Apple's server quotas, tile transfer
status, or 3DGS use. A lack of tile render callbacks can mean cached imagery.


## Three-API camera constraint comparison

The iPhone/iPad UI includes **Pitch制限の突破検証：3つのカメラAPI**.
Tap **3方式を自動比較**. It compares 18 tests at fixed location/heading:

- \`MKMapCamera(lookingAtCenter:fromDistance:pitch:heading:)\`
- \`MKMapCamera(lookingAtCenter:fromEyeCoordinate:eyeAltitude:)\` with an eye location and altitude chosen for an approximately 89° sightline
- A separate **SwiftUI \`Map(position:)\`** using \`MapCamera(centerCoordinate:distance:heading:pitch:)\` and \`.onMapCameraChange(frequency: .continuous)\`

Distances: 50, 200, 500, 1200, 3000 and 10000 meters. Each requests
89° (eye coordinate method is geometrically estimated) and records the
constructed pitch, immediate applied pitch and settled pitch. UIKit MapKit
additionally records the last render callback pitch when available; SwiftUI
MapCamera does not expose a public per-tile rendering completion callback.

All measurements are logged as \`PITCH_PROBE.*\` JSONL entries and written
row-by-row to \`Documents/FlyoverPitchLab/CameraConstraintProbe-latest.csv\`.
Use **比較結果CSVを共有** to export; previous CSV can be exported after relaunch
if a LiveContainer guest was terminated mid-run. The probe can be cancelled.

This **does not bypass Apple's camera safeguards**, use private APIs, or
prove 3DGS availability. The goal is to locate whether the clamping occurs
during camera creation, map assignment or rendering. SwiftUI \`Map\`
uses realistic imagery rather than necessarily the same exact legacy
satelliteFlyover renderer, so its results are not a perfect renderer-level A/B.
